# NikaS Specialized Panel UI Standard v1.6 — LIDER snapshot

**Status:** REQUIRED  
**Source:** NikaS synchronized specialized-panel standard  
**Shell:** v1.6 · **Zoom:** v1.3

## Оболочка

- safe area учитывается ровно один раз;
- Header расположен ниже Dynamic Island/чёлки;
- слева только системная кнопка `☰`, отправляющая `hass-toggle-menu`;
- справа остаётся кнопка обновления;
- центральная плашка геометрически центрирована независимо от боковых кнопок;
- Header и нижнее меню не масштабируются и не перемещаются вместе с рабочей областью;
- нижнее меню полноширинное, фиксированное и расположено выше Home Indicator;
- минимальная высота интерактивной области Header — 44 px.

## Центральная плашка Header и возврат в NikaS

Специализированная панель открывается из базовых панелей `Дом сейчас`, `Действия` или `Инфраструктура`. Центральная плашка является постоянной кнопкой возврата именно в ту базовую панель NikaS, из которой пользователь пришёл.

- центральный заголовок оформляется как кликабельная плашка;
- стрелка и отдельная надпись `Назад` не используются;
- первая строка — название текущей специализированной панели;
- вторая строка — версия интерфейса в формате `UI vX.Y.Z`;
- нажатие на всю плашку возвращает в исходную базовую панель NikaS;
- допустимые базовые маршруты: `/dashboard-house`, `/dashboard-actions`, `/dashboard-infrastructure` и их вложенные представления;
- исходный маршрут определяется и сохраняется один раз при открытии специализированной панели;
- рекомендуемый явный контракт открытия — `return_to` или `from` в URL либо одноразовая передача маршрута через `sessionStorage` ключ `nikas.specialized.source_route.v1`;
- допустимый same-origin referrer может использоваться как дополнительный источник;
- при прямом открытии применяется заранее заданный `parent_route` панели;
- `history.back()` запрещён;
- возврат выполняется явной навигацией Home Assistant через `history.pushState()` и событие `location-changed`;
- сохранённый маршрут не пересчитывается при обновлении телеметрии;
- обновление `hass` не пересоздаёт Header, центральную плашку и её обработчик.

Для LIDER безопасный маршрут прямого открытия — `/dashboard-infrastructure/overview`.

## Масштабирование

- масштабируется одна рабочая область целиком;
- pinch двумя пальцами выполняется относительно точки между пальцами;
- масштаб 75–200%, по умолчанию 100%;
- экранных кнопок масштаба нет;
- двойное касание двумя пальцами возвращает 100% и начало координат;
- завершение pinch в диапазоне 97–103% фиксирует ровно 100%;
- сброс кратко показывает `Масштаб 100%`;
- масштаб хранится локально для панели/клиента;
- увеличение допускает панорамирование.

## Диагностика

- специализированная панель может иметь отдельную вкладку `Диагностика`;
- технический экран не заменяет эксплуатационные вкладки;
- для задействованных сущностей показываются текущее `state`, все доступные `attributes`, временные метки состояния и контекст Home Assistant;
- диагностический экран не скрывает raw, энергетические или сервисные атрибуты только потому, что они не используются в основном UI;
- нажатие на сущность открывает нативный Home Assistant `more-info`;
- изменение диагностических значений обновляет только рабочую область и не пересоздаёт оболочку панели.

## Семантика

- обычные измерения нейтральны;
- зелёный, жёлтый, оранжевый и красный применяются только после достоверной классификации;
- `unknown`, `unavailable`, устаревшие и отсутствующие источники не считаются нормой;
- неподтверждённые значения не создаются;
- фактические параметры открывают нативный Home Assistant `more-info`.

## Стабильный DOM и отсутствие мерцания

- оболочка `Header → zoom-viewport → Bottom Tab Bar` создаётся один раз и сохраняет идентичность DOM;
- `shadowRoot.innerHTML` допускается только при первоначальном монтаже;
- `set hass()` обновляет только существующие текстовые узлы, классы, лампы, атрибуты и значения;
- изменение возраста телеметрии и очередной опрос не пересоздают вкладку, изображение, zoom-viewport, Header или нижнее меню;
- точное число секунд возраста не входит в ключ структурной перерисовки;
- двухуровневый индикатор обновляется только при смене категории связи или актуальности;
- изображения не получают повторно `src`, если сам ресурс не изменился;
- прокрутка, инерция, pinch и pan не прерываются структурной перерисовкой;
- нижнее меню остаётся постоянным DOM-узлом вне прокручиваемого viewport;
- задержка полной перерисовки не считается исправлением мерцания: фоновые обновления должны быть точечными.

## Приёмка

Основное устройство приёмки — Home Assistant Companion App на iPhone Pro Max в портретной ориентации. Проверяются safe area, системное меню, центральная плашка возврата, нижнее меню, pinch/pan/reset, сохранение масштаба, явные состояния недоступности, полный технический экран диагностики, отсутствие дублирования оболочки и отсутствие миганий, скачков или смещения нижнего меню при опросе, прокрутке и инерции.
